# Progress Log

## Learnings
(Patterns discovered during implementation)
- Project uses Jest for testing, run with `npm test -- tests/<file>.test.js`
- No TypeScript in project - "Typecheck passes" criterion is satisfied by default
- Existing tests for canvas.test.js, combos.test.js, pipeline.test.js have pre-existing failures (ffmpeg/font issues)
- Config files go in `config/` directory, config modules in `src/config/`
- Deep merge utility needed for combining default config with user overrides

## Iteration 1 - US-001: Create JSON Configuration Schema and Loader
- What was implemented:
  - Created `src/config/schema.js` with complete schema definition for text, images, and animation settings
  - Created `src/config/configLoader.js` with loadConfig, loadDefaults, deepMerge functions
  - Created `config/defaults.json` with default values (needed for configLoader to work)
  - Created `tests/config.test.js` with 43 unit tests covering schema validation and merging logic
- Files changed:
  - src/config/schema.js (new)
  - src/config/configLoader.js (new)
  - config/defaults.json (new)
  - tests/config.test.js (new)
- Learnings for future iterations:
  - configLoader requires defaults.json to exist before it can be used
  - Schema validates types (string, number, boolean, object), ranges (min/max), and enums
  - deepMerge handles nested objects recursively while preserving immutability
  - Test fixtures should be created in beforeAll and cleaned up in afterAll

## Iteration 3 - US-003: Integrate Config Loader into Video Processing Pipeline
- What was implemented:
  - Updated `processComboVideo` signature to accept optional `configPath` parameter (9th parameter)
  - Added `loadConfig` import and call at start of processing
  - Updated `redrawFrameWithComboImages` to accept and use config object
  - Updated `calculateInputImagesDimensions` to accept spacing parameter from config
  - Updated `drawInputImages` to use spacing between images
  - Updated `drawBlurredBackground` to use configurable padding
  - Maintained backward compatibility - existing calls without config continue to work
  - Added integration tests verifying config loading and application
- Files changed:
  - src/video/videoUtils.js (added configPath parameter, config loading, passing config to functions)
  - tests/configurable-params.test.js (updated tests for new calculateInputImagesDimensions logic, added integration tests)
  - PRD.md (marked US-003 as complete)
- Learnings for future iterations:
  - Config values should be resolved early (in processComboVideo) and passed to child functions
  - The `null` check pattern (`config ? config.images.width : defaultValue`) allows backward compatibility
  - The old calculateInputImagesDimensions had quirky logic (+20 constant); new logic is cleaner (numInputs * width + gaps * spacing)
  - Integration tests should verify both config loading and the effect on downstream calculations
